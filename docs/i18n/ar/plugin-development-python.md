# دليل تطوير المكوّن الإضافي كعملية خارجية في SpeedMQ —— Python

> **الجمهور**: المطوّرون الذين يكتبون مكوّنًا إضافيًا كعملية خارجية (sidecar) لـSpeedMQ بلغة Python.
> **اقرأ أولًا**: [دليل تطوير المكوّن الإضافي كعملية خارجية (sidecar)](plugin-development.md) —— فهناك شُرح النموذج الذهني وحقول الإعداد والجدول الكامل لبروتوكول السلك؛
> أما هذا المستند فيشرح فقط **كيفية التنفيذ بلغة Python**، والخطوات والنتائج المُختبَرة محليًا.
> **المشروع النموذجي**: في مساحة العمل `speedmq-plugin/python/sidecar_plugin.py` (المكتبة القياسية فقط، بلا أي اعتماديات خارجية).

---

## 1. كيف يبدو عند تشغيله

```
内核进程 ──dial(tcp 本机地址)──► 你的 Python 进程（sidecar.NewServer 的等价物：一个 TCP 服务端）
   ▲                                    │
   │  握手 / 心跳 / 控制面调用（JSON）      │
   │◄───────────────────────────────────┤  反向调用 core.authenticate / session.*（JSON）
   │      客户端字节流（原始字节，不 base64） │
   └────────────────────────────────────┘
```

ثلاث نقاط أساسية (يسهل الخطأ فيها، فاحفظها جيدًا):

1. **عمليتك هي الخادم**: تستمع إلى عنوان محلي وتنتظر اتصال النواة (`plugins.<الاسم>.sidecar.address`).
2. **منفذ الأعمال الخارجي تفتحه النواة**: العملاء يتصلون بمنفذ النواة، وتُوسَّط البايتات إليك (`protocols[].listeners`).
3. **يجب أن يكون `prefix` غير فارغ**: تحدّد النواة بالبادئة "مَن تُسلَّم إليه هذه الاتصال". و`prefix` الفارغ يعني **عدم المشاركة في الاستكشاف**،
   ولن يُسلَّم إليك الاتصال حتى على مستمعه الخاص (عمليًا: يُقطع الاتصال فورًا). وطول البادئة ≤ 8 بايتات، ASCII.

## 2. التشغيل في ثلاث خطوات

### الخطوة الأولى: الإعلان عن المكوّن الإضافي في الإعداد

`speedmqd.json` (**الإعداد الفعلي هو JSON قياسي، ولا يقبل التعليقات**):

```json
{
  "plugins": {
    "py-sidecar": {
      "builtin": false,
      "enabled": true,
      "sidecar": {
        "address": "tcp://127.0.0.1:19001",
        "spawn": ["python", "/opt/speedmq/sidecar_plugin.py", "-addr", "0.0.0.0:19001"],
        "protocols": [
          { "name": "pyecho", "prefix": "PY",
            "listeners": [{ "name": "pyecho", "addr": ":19002" }] }
        ]
      }
    }
  }
}
```

- `address` هو **العنوان الذي تتصل به النواة إليك** (النواة عميل، والمكوّن الإضافي خادم).
- `spawn` فارغ = النواة تتصل فقط ولا تُطلق، وتدير العملية بنفسك (systemd / supervisor / compose).
- `prefix` **يجب أن يكون غير فارغ**: يجب أن تبدأ البايتة الأولى من العميل به (وتحدّد النواة بالبادئة الاستكشافية مَن تُسلَّم إليه الاتصال).
- `listeners` هي المنافذ الخارجية، وتفتحها النواة (العميل يتصل بالنواة، لا بك).
- عند النشر عبر الحاويات يستخدم `address` **اسم الخدمة** (مثل `tcp://py-sidecar:19001`)، ويجب أن يستمع المكوّن الإضافي إلى `0.0.0.0`.

### الخطوة الثانية: التشغيل

```bash
# 由内核 spawn 时不用手起；手动调试：
python sidecar_plugin.py -addr 0.0.0.0:19001 -name py-sidecar -session-demo
```

### الخطوة الثالثة: التحقّق

```bash
curl -u guest:guest http://127.0.0.1:15672/api/plugins | python -m json.tool   # state 应为 enabled
printf 'PYhello\n' | nc 127.0.0.1 19002                                       # 应回显 PYhello
```

## 3. نقاط التنفيذ

### 3.1 تأطير الرسائل (طبقة البايت الوحيدة التي يجب أن تكتبها بشكل صحيح)

```
+--------+--------+------------------+
| len    | kind   | payload          |
| u32 BE | u8     | (len-1) 字节      |
+--------+--------+------------------+
len = 1 + len(payload)（长度字段**包含** kind 字节）；单帧上限 16 MiB。
```

حمل إطار البيانات = `4 بايتات بترتيب كبير لرقم التدفّق + بايتات خام`؛ وحمل مستوى التحكّم هو JSON.

```python
def read_frame(sock):
    head = read_exact(sock, 5)
    if len(head) < 5:
        return None
    (length,) = struct.unpack(">I", head[:4])
    payload = read_exact(sock, length - 1)
    return head[4], payload          # (kind, payload)
```

### 3.2 المصافحة ونبضات القلب

بعد اتصال النواة **ترسل `Hello` أولًا**، وعليك الردّ بإطار `HelloAck`؛ وتتحقّق النواة من
`name == اسم المكوّن الإضافي في الإعداد` ومن `api_version == APIVersion الخاص بالنواة` (حاليًا `v1`).
بعد ذلك ترسل النواة `Ping` كل 2s، ويكفي أن تردّ بـ`Pong` (وعدم الردّ يُعدّ موتًا).

### 3.3 التدفّق المنطقي

وصول `kindOpen` → **رُدّ بـ`OpenAck` أولًا**، ثم ابدأ الخدمة؛ ووصول `kindData` → اكتبه كما هو (أو بعد تحليله وفق بروتوكولك) مرة أخرى إلى
`kindData`؛ وعند انتهاء المعالجة → أرسل `kindClose`. والتدفّق الواحد = اتصال عميل واحد.

### 3.4 الاستدعاء العكسي وجسر دلالات النواة

تمرّ الاستدعاءات من المكوّن الإضافي → النواة عبر `kindCall` مع `"reverse": true`، وتردّ النواة بـ`kindReply` على الاتصال نفسه.
**والترتيب مهم**:

```
core.authenticate → session.open → session.declare_queue / publish / consume / …
```

ولا يمكن **إغفال** `core.authenticate`: فلا هوية لسطح عمليات النواة للاتصال قبل المصادقة، وسيُرفض `session.open` مباشرةً
(`ACCESS_REFUSED - access to vhost '/' refused for user ''`). والمعاملات هي استجابة SASL التي استخرجتها من بروتوكولك:

```python
plain = b"\x00" + user.encode() + b"\x00" + password.encode()
ident = call("core.authenticate", {
    "stream": stream_id, "mechanism": "PLAIN",
    "response": base64.b64encode(plain).decode(),   # 字节在 JSON 里是 base64
})
# 拿到的会话与进程内协议插件完全同一套语义
call("session.open", {"stream": stream_id, "vhost": "/"})
q = call("session.declare_queue", {"stream": stream_id, "exclusive": True, "auto_delete": True})
call("session.publish", {"stream": stream_id, "routing_key": q["name"],
                         "message": {"body": base64.b64encode(b"hi").decode()}})
call("session.consume", {"stream": stream_id, "queue": q["name"], "prefetch": 32})
```

وتُعاد تسليمات الاستهلاك من النواة **باستدعاء أمامي** (`kindCall`، `method = "session.deliver"`)، وبعد المعالجة تُسوّى بـ
`session.settle` (`ack` / `requeue` / `reject`؛ ورقم التسليم فريد عالميًا، ولا يحتاج رقم تدفّق).

### 3.5 نموذج التزامن (نسخة Python)

| الدور | الخيط |
| --- | --- |
| حلقة قراءة الإطارات | واحد لكل اتصال نواة |
| معالجة التدفّق | واحد لكل تدفّق (ولذلك يمكن تزامن عدة اتصالات عملاء) |
| معالجة الاستدعاء الأمامي | واحد لكل استدعاء |

**ويجب الانتباه**: **لا يجوز** انتظار ردّ الاستدعاء العكسي بشكل متزامن داخل حلقة القراءة (سيحدث جمود) —— فالاستدعاء الأمامي (`session.deliver`)
يجب إرساله إلى خيط مستقل للمعالجة، لأنه قد يشرع أثناء معالجته في استدعاء `session.settle` آخر. ويجب أن تكون كتابة الإطارات مقفلة ومتسلسلة.

## 4. قراءة الشيفرة (المشروع النموذجي)

يبلغ `speedmq-plugin/python/sidecar_plugin.py` نحو 320 سطرًا، والدوال المهمة:

| الموضع | الوظيفة |
| --- | --- |
| `read_frame` / `Conn.send` | قراءة وكتابة الإطارات (بادئة الطول + kind) |
| `Conn.call` | الاستدعاء العكسي: ترقيم → إرسال → انتظار الرد (بالمطابقة عبر `reverse=true` و`id`) |
| `Conn.serve` | حلقة قراءة الإطارات والتوزيع |
| `Conn._handle_hello` | التحقّق من اسم المكوّن الإضافي/إصدار الـ API والردّ بـHelloAck |
| `Conn._handle_open` / `_serve_stream` / `_echo` | دورة حياة التدفّق والصدى |
| `Conn._dispatch` | معالجة الاستدعاء الأمامي: `session.deliver` (مع settle) و`stats` |
| `Conn._session_demo` | المصادقة + الإعلان عن طابور + النشر + الاستهلاك |

## 5. اختبار فعلي (إعادة الإنتاج محليًا)

البيئة: Windows + Python 3.12؛ والنواة تعمل في Docker (`speedmq:1.1.01`)، والمكوّن الإضافي يعمل على المضيف،
وتتصل به النواة عبر `tcp://host.docker.internal:19001`.

```
plugin=py-sidecar state=enabled           # /api/plugins
echo=[PYhello]                            # 客户端连内核端口 19002 发 "PYhello\n"

--- 插件 stdout ---
sidecar 已启动 plugin=py-sidecar addr=0.0.0.0:19001 version=0.1.0
内核已接入 plugin=py-sidecar peer=('127.0.0.1', 52864)
握手完成 plugin=py-sidecar kernel=1.1.01
认证通过 user=guest
session 演示完成 queue=amq.gen-9e5d0d695639bad12ce919
收到投递（session.deliver） queue=amq.gen-9e5d0d695639bad12ce919 delivery_id=1 body=hello from python sidecar
流已打开 plugin=py-sidecar stream=1 remote=172.17.0.1:43856 local=172.17.0.2:19002
```

المسار المُغطّى: **المصافحة → المصادقة → جسر الدلالات (الإعلان/النشر/الاستهلاك) → إعادة دفع التسليم → التسوية → صدى تدفّق البايتات**.

## 6. ملاحظات خاصة بلغة Python

- **لا تستخدم `time.sleep` لانتظار نبضات القلب**: حلقة القراءة حاجبة، ويكفي الاعتماد على Ping من النواة لإبقاء الاتصال؛
  وإن ضبطت مهلة قراءة للـsocket فتذكّر أن تعالج المهلة على أنها "انتهاء الاتصال" (فقد لا يُغلق الـsocket فورًا عند `kill -9` للنواة).
- **`json.dumps` يضيف مسافات افتراضيًا**: استخدام المثال لـ`separators=(",", ":")` هو فقط لتحسين مظهر السجل، والبروتوكول نفسه لا يشترطه.
- **البايتات هي base64**: كلٌّ من `message.body` و`core.authenticate.response` سلسلة base64 داخل JSON،
  فلا تنسَ `base64.b64encode/decode`.
- **يجب قفل كتابة الإطارات**: فنبضات القلب والردود وكتل البيانات تأتي من خيوط مختلفة، والكتابة المتداخلة تُفسد الاتصال كله (ويستخدم المثال `threading.Lock`).
- يمكن استخدام `asyncio` أيضًا، لكن مع ضمان "كتابة متسلسلة + حلقة قراءة غير حاجبة"، والمنطق نفسه في النسخة الخيطية.

## 7. متقدّم

- إن أردت تزويد المكوّن الإضافي بواجهة إدارة خاصة به: أضف `console_url` في الإعداد، وستظهر مدخل مباشر في صفحة «إدارة المكوّنات الإضافية» بلوحة الإدارة
  (انظر المستند الرئيسي §5.8).
- إن جعلت المكوّن الإضافي خدمة مستقلة يديرها systemd / K8s: `spawn: []` + `restart: "never"`، ويُطلق من الخارج.
- عند الحاجة إلى تعايش عدة بروتوكولات: اجعل عدة مكوّنات إضافية تستخدم `prefix` مختلفة على المستمع نفسه، أو افتح لكل منها منفذًا مخصّصًا.
